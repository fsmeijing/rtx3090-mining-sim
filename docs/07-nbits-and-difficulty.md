# 7. nBits 和难度目标

## 目标 T：一把"及格线"

挖矿不是"算出某个特定哈希"，而是"算出一个**足够小**的哈希"。
这个及格线就是**目标（Target，记作 T）**：H ≤ T 才算挖到。

T 越小，及格越难（想想：随机哈希落进一个更小的区间，概率更低）。

## nBits：T 的压缩写法

T 是 256 位的大数，写出来太长。比特币用 4 字节的 **nBits** 压缩表示：

```
nBits = 0x1d00ffff
         │   └── 尾数 mantissa = 0x00ffff（3 字节）
         └────── 指数 exponent = 0x1d = 29（1 字节）

T = mantissa × 256^(exponent − 3) = 0xffff × 256^26
```

展开就是创世目标（完整 64 位十六进制）：

```
00000000ffff0000000000000000000000000000000000000000000000000000
```

前 8 个十六进制 0 —— 换算成二进制有 **32 个前导零**。

本项目代码（`bitcoin_pow/target.py`）：

```python
target, non_canonical = nbits_to_target(0x1D00FFFF)
print(hex(target))
# 0x00000000ffff0000000000000000000000000000000000000000000000000000
```

## 难度如何调整？

每 **2016 个区块**（约两周），全网按"最近 2016 块实际用了多久"调整一次
nBits：出块快了 → 调小 T（更难）；出块慢了 → 调大 T（更简单）。
目标是把出块间隔稳定在约 10 分钟。

高度 0–19 的区块 nBits 全部是 0x1d00ffff（难度 1），
因为还没到第一个调整点（2016 块）。

## 本项目的三档教学难度

创世难度（平均要试 2³² ≈ 43 亿次）对课堂太狠，我们提供了放大版目标：

| 模式 | 目标 | 平均尝试次数 | 体感 |
|---|---|---|---|
| easy | T_genesis << 24 | ~256 次 | 一眨眼 |
| medium | T_genesis << 12 | ~100 万次 | CPU 1 秒内 |
| genesis | 原始 T | ~43 亿次 | CPU 数小时，GPU <1 秒 |

注意方向：**目标左移 → 数值变大 → 更容易命中**（虽然目标自己的
前导零变少了，但"哈希要小于它"的区间更大了）。

## 验证一下

```bash
python3 -m bitcoin_pow --mode genesis --max-attempts 100000
# 会如实报告"尝试 10 万次未找到解"——难度 1 也不是白给的
python3 -m bitcoin_pow --mode medium --max-attempts 2000000
# CPU 几秒内命中
```
