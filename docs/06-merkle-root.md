# 6. Merkle Root（默克尔根）

## 为什么需要它？

一个区块里可能有几千笔交易。如果区块头的"指纹"要把所有交易都装下，区块头就会大得没法高效处理。**Merkle Root** 解决了这个问题：把全部交易折叠成**一个 32 字节的指纹**放进区块头。

## 怎么折叠？（两两配对比赛）

想象一场淘汰赛：

1. 每笔交易的哈希是"参赛选手"；
2. 两个一组：`H = SHA256(SHA256(左 + 右))`，胜者（哈希）晋级；
3. 不足一对的，单独复制一份配对；
4. 决赛冠军就是 **Merkle Root**。

```
tx1  tx2  tx3  tx4
 \   /     \   /
  H12       H34        两两配对
    \       /
     H1234            决赛
       |
   MerkleRoot         放进区块头
```

## 为什么它厉害？

- **改一笔交易 → 根全变**：区块头指纹失效，之前挖的 Nonce 全部作废；
- **快速证明**（Merkle Proof）：不需要下载整个区块，
  只需约 log₂(N) 个中间哈希，就能证明"某笔交易在这个区块里"。
  10 万笔交易只需 17 个哈希。

## 创世区块的默克尔根

```
4a5e1e4baab89f3a32518a88c31bc87f618f76673e2cc77ab2127b7afdeda33b
```

创世区块只有一笔交易（Coinbase，含那段泰晤士报标题），所以它的
"淘汰赛"只有一名选手——根就是这笔交易自己的哈希（单节点直接晋级）。

## 和挖矿的关系

默克尔根是区块头的第 3 个字段（字节 36–68）。**挖矿时它必须固定**：
每换一次默克尔根，就是一道全新的题。真实矿池靠给不同矿工发不同的
Coinbase 交易（改 ExtraNonce，见 docs/03）来制造不同题面，
而本实验固定创世区块头、只转动 Nonce 旋钮。
