# 3. Nonce 和 ExtraNonce

## Nonce：挖矿时唯一"自由"的旋钮

区块头 80 字节里，前 76 字节（版本、前块哈希、默克尔根、时间、难度）在挖矿时是**定死的**——你改了任何一个，就是在挖"另一道题"。只有最后 4 字节 **Nonce**（Number used once，一次性数字）是挖矿者可以随便改的。

挖矿 = 不停地改 Nonce、算哈希、比大小，直到 H ≤ T：

```
for nonce in 0..4294967295:
    H = SHA256(SHA256(区块头 with nonce))
    if H <= T: 成功！
```

## Nonce 有多大？

Nonce 只有 **4 字节 = 32 位**，一共 4,294,967,296（约 43 亿）种取值。
听起来很多，但现代矿机一秒就能试几万亿次——所以 2012 年后矿工们
还在区块头之外另辟了空间改数据（见下文 ExtraNonce），并改用
"版本号滚动"（version rolling）等技巧扩大搜索范围。

## 亲手转一转这个旋钮

```bash
# easy 模式：目标被放大了 2^24 倍，平均试 256 次就中
python3 -m bitcoin_pow --mode easy --max-attempts 100000
# 命中 Nonce    : 236
# 成功哈希 H    : 005ba61e89aae83d3d9c841f2d4960d41a26265f885fe3a72d65987e4764ea52
```

注意每次运行 Nonce 起点、目标都固定，所以结果完全一样（确定性）。

## ExtraNonce 是什么？

创世区块的 Coinbase 交易（第一笔交易）里有一段备注：

> "The Times 03/Jan/2009 Chancellor on brink of second bailout for banks"
> （泰晤士报 2009-01-03：财政大臣站在第二轮银行救助的边缘）

这段话既证明了创世区块诞生时间，也顺便解释了 ExtraNonce：
挖矿程序在**交易数据**里预留了一个可以改的计数器字段（ExtraNonce）。
改它 → 默克尔根变 → 区块头变，相当于"第二个 Nonce"。

本实验**只用 4 字节 Nonce**（教学够用），ExtraNonce 的原理记录在此，
帮助理解真实矿机为什么能突破 43 亿的上限。

## 创世 Nonce 的巧合

本项目 GPU 实测（见 docs/10）从 0 开始顺序扫描，
在真实创世难度下命中的正是 **Nonce = 2,083,236,893** ——
中本聪 2009 年用的就是它。这不是巧合，是确定性计算 + 真实数据
的必然结果，也是对实现正确性的最强检验。
